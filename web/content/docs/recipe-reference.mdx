Assertions are declared under `chainValidation` in a Harness recipe, `.harness/spec.yaml`. Everything outside `chainValidation` follows the standard [Harness recipe format](https://github.com/akm2006/hedera-harness/blob/feat/deterministic-onchain-postconditions/docs/authoring-a-recipe.md). Recipes declare `schemaVersion: 3`.

## Complete example

```yaml title=".harness/spec.yaml"
schemaVersion: 3
name: bond-transfer-policy
# ...baseline, validators, and the rest of the recipe

chainValidation:
  enabled: true
  network: testnet
  operator:
    accountIdEnv: HEDERA_OPERATOR_ID
    privateKeyEnv: HEDERA_OPERATOR_KEY
  fundingHbar: 10
  sweepBack: true
  expose:
    browserLocalStorageKey: burnerWallet.pk
    envVars: []
  actors:
    attacker: { fundingHbar: 5 }
    complianceOfficer: {}
  assertions:
    - id: reject-unverified-transfer
      description: Unverified investor must not receive the bond
      actor: attacker
      action:
        name: attempt-transfer-to-bob
        command: yarn hardhat run scripts/transfer-to-bob.ts --network hederaTestnet
        timeoutMs: 60000
      expect:
        outcome: mustRevert
        reasonContains: KYC
    - id: coupon-balance-delta
      action:
        name: run-coupon
        command: yarn hardhat run scripts/pay-coupon.ts --network hederaTestnet
      expect:
        outcome: mustSucceed
        balanceDelta:
          accountEnv: ALICE_ACCOUNT_ID
          asset: hbar
          equals: "500000000"
```

## Environment for action commands

Harness runs each action with the executing signer: the assertion's `actor`, or the primary signer when `actor` is omitted.

| Variable | Value |
| -------- | ----- |
| `HARNESS_SIGNER_ACCOUNT_ID` | The signer's Hedera account ID |
| `HARNESS_SIGNER_EVM_ADDRESS` | The signer's EVM address |
| `HARNESS_SIGNER_PRIVATE_KEY` | The signer's ECDSA private key |
| Each name in `expose.envVars` | The same private key, for tooling that expects its own variable name |

Harness redacts these keys from findings, reports, and repair prompts.

## Load-time checks

The recipe loader rejects these before any HBAR is spent:

- `network` set to anything other than `testnet`
- an `actor` that is not declared in `chainValidation.actors`
- `reasonContains` combined with `outcome: mustSucceed`
- a `balanceDelta` with both `account` and `accountEnv`, or neither
- an `equals` value that is not a signed integer string

## Before a full run

A full Harness run can take 40 minutes to two hours. Check the recipe cheaply first:

```bash
hedera-harness doctor     # Node, git, agent CLI, the recipe, and every referenced path
hedera-harness validate   # ASSERT only, no agent
```

The operator must be an **ECDSA** account; ED25519 has no EVM alias. `@hiero-ledger/sdk` ships with `hedera-harness`, so do not add it to the project under test.
