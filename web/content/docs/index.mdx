PolicyProbe adds deterministic on-chain postcondition assertions to [Hedera Harness](https://github.com/hedera-dev/hedera-harness). A recipe declares an action, the signer that runs it, and the outcome that must follow: the transaction must succeed, must revert, or must move an exact balance. Harness executes the action on Hedera testnet, reads the consensus result from Mirror Node, and compares it with the declaration in code.

## The gap it closes

A command that exits `0` proves the command finished. It does not prove the deployed application enforced the rule it was built to enforce.

Consider a tokenized bond that must reject transfers to unverified investors. If the bond is deployed with its whitelist disabled, the deploy succeeds, a forbidden transfer succeeds, and every process in the pipeline exits cleanly. Harness's semantic `EVALUATE` stage can inspect evidence, but a recipe had no way to state that *this action, signed by this account, must revert* and receive a deterministic verdict when it does not.

## One assertion

```yaml title=".harness/spec.yaml"
chainValidation:
  enabled: true
  network: testnet
  actors:
    attacker: { fundingHbar: 5 }
  assertions:
    - id: reject-unverified-transfer
      actor: attacker
      action:
        name: attempt-transfer
        command: npx tsx scripts/transfer.ts
      expect:
        outcome: mustRevert
```

The recorded ATS comparison ran the same `reject-unverified-transfer` assertion against two bonds that differ only in whitelist configuration:

| Configuration      | Declared     | Observed on Mirror Node    | Verdict                                           |
| ------------------ | ------------ | -------------------------- | ------------------------------------------------- |
| Whitelist disabled | `mustRevert` | `SUCCESS`                  | Finding `chain-assertion:reject-unverified-transfer` |
| Whitelist enabled  | `mustRevert` | `CONTRACT_REVERT_EXECUTED` | Pass                                              |

The transaction hashes for both runs are listed in [Testnet evidence](/docs/evidence).

<Callout title="Scope">
  PolicyProbe verifies technical behavior on Hedera testnet. It does not certify legal or regulatory compliance.
</Callout>
